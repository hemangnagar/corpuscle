# Architecture decisions

| # | Decision | Chosen | Why |
|---|---|---|---|
| 1 | Execution engine | PySpark with local mode | Enterprise and government corpora are terabytes; retrofitting distribution into a metric engine is the rewrite that stalls Phase 3 |
| 2 | Corpus identity | Merkle root over sorted SHA-256 document hashes | Order-independent; single-document membership proofs; subsets and derivatives verify on their own |
| 3 | Signing envelope | DSSE over an in-toto Statement v1 | Mature tooling, same semantics as SLSA attestations, pluggable signers |
| 4 | Records keyed by content hash | yes | Survive renames, moves, transfers and subsetting |
| 5 | v0 detector pins | GlotLID 3.0, datasketch MinHash 128/5-gram/0.8, textstat 0.7.4, Presidio 2.2.358 + en_core_web_lg, ftfy 6.3.1, tiktoken o200k_base | Each changes the numbers; each is recorded per run |
| 6 | The existing profiler's metrics | Reimplemented from open components, kept as `baseline` IDs, with English readability scoped to the English slice and MTLD added beside TTR. First counted as 54; reconciled to 105 in decision 12 | Continuity for reviewers; corrected methods are defensible in front of an auditor |
| 7 | Bundle format | Plain JSON and JSON Lines, detached signatures | Passes cross-domain guards that whitelist by schema |
| 8 | Agents | Never compute a number, never write to the bundle; every action logged into `agent_runs` | Reproducibility and audit cover the agents, not only the metrics |
| 9 | Phase order | Language, duplication, integrity, compliance and provenance ship in Phase 1; descriptive, lexical and readability move to Phase 2 | The first result a buyer sees must be one a model cannot produce about its own corpus. Word counts and readability invite "the model can do that"; a marking ceiling breach or a 40% near-duplicate rate does not. The marking metrics pull a plain-text banner and portion-mark parser into Phase 1; the ISM XML parser stays in Phase 4. Continuity with the 54 baseline metrics waits one phase, and costs nothing downstream because their IDs and method versions are already fixed in the catalog |
| 10 | Policy is separate from pipeline configuration | A policy file (`policy/*.yaml`) says which measured values count as a finding and at what severity; which analyzers ran and with which pins is recorded in `manifest.run` | Other profilers mix the two in one steps-and-thresholds config, so a finding cannot be regenerated without the run. Splitting them lets the same signed measurements be judged under several policies, and lets the policy's id, version and hash be signed beside the results. A metric the run did not report yields an inconclusive finding rather than silence |
| 11 | Near-duplicate candidate net | LSH indexed 0.2 below the confirmation threshold with recall-weighted banding; every candidate confirmed against the estimated Jaccard at the threshold itself | Banding at the threshold misses pairs just above it (a 0.87 pair in the fixture); recall must depend on the MinHash estimate, not on banding luck. The cost is candidates, which LSH still bounds |
| 12 | Coverage of the existing profiler | Catalog reconciled against its full list (105 metrics: textstat 40, spaCy 54, tiktoken 3, language, data health 3, duplicates 2). Added: Spache and consensus grade; corpus totals for words, sentences and syllables; an `entities` family of 19 spaCy NER densities per 1k tokens; salient terms; empty and large document counts; duplicate source-id count | Nothing a reviewer already gets may go missing. Entity densities are counts, never entity text, so they sit beside PII without storing values. Duplicate source ids are a provenance defect (same id, different bytes) and are kept apart from content duplication. Spache and text_standard are English-only and scoped like the other formulas |
| 13 | Agent tool surface | Six calls in `corpuscle.tools`: list_findings, get_finding, get_record, read_document, diff_documents, propose. Every call is logged as (tool, args_hash, result_hash); propose is the only write and cannot carry observed, threshold, status or severity | The surface is the product boundary: our agent, a customer's agent over MCP and a future planner all get the same calls, the same log and the same approval gate. Hashing arguments and results rather than storing them keeps document text and PII out of the manifest while still binding the run to what the agent saw |
| 14 | Approval amends, never rebuilds | `manifest.amend` adds assessment, narrative, remediation and approver to a finding and appends the agent run, then re-signs; it refuses any other change | Re-running `build` would let an approval silently pick up new detector versions or a changed corpus. Amending keeps the Merkle root, records hash and results byte-identical, so an approved manifest is the original measurement plus a signed human decision |
| 15 | No proposal is still a record | An investigation that ends without a proposal, is cut off, or is refused by the model submits an inconclusive proposal with the reason | Same principle as the gate's inconclusive findings: an auditor should see that the question was asked and not answered, not an empty log |
| 16 | datasketch pinned below 2.0 | `datasketch>=1.6.5,<2` | 2.0 changes the MinHash scheme and refuses to rebuild a signature from hash values without one. Different permutations mean different near-duplicate numbers, so moving to 2.x is a method_version bump for the duplication family with a re-baseline, not a dependency refresh. Found by a fresh install during the first live triage run |
| 17 | Fixture bytes are pinned | `.gitattributes` marks `tests/fixtures/**` as not-text, and a test pins the fixture corpus's Merkle root | A Windows checkout with autocrlf gave the two multi-line fixtures CRLF endings and a different corpus identity (`17c17200…` instead of `d0ad1492…`), confirmed by reproducing it byte for byte. Real corpora never pass through git, but fixtures do, and a content-addressed test corpus must hash the same everywhere |
